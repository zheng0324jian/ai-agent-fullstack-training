## 2. A1：双协议、双模型

### 2.1 模型 A（OpenAI Responses API）

```bash
curl -s http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "pro",
    "messages": [{"role": "user", "content": "用一句话解释什么是 LLM Gateway"}],
    "temperature": 0.2,
    "max_tokens": 200
  }'
```

### 2.2 模型 B（Anthropic Messages API）

```bash
curl -s http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "flash",
    "messages": [{"role": "user", "content": "用一句话解释什么是 LLM Gateway"}],
    "temperature": 0.2,
    "max_tokens": 200
  }'
```

### 2.3 检查点

- [ ] 两个请求都返回 200
- [ ] 响应结构一致（同一套字段）
- [ ] 响应或日志中能看到实际 `provider` / `protocol`
- [ ] 两次调用走的是不同上游端点/协议，而不是同一 SDK 换模型名
- [ ] 客户端代码只改了 `model`

**证据建议**：保存两次响应 JSON、上游请求日志（脱敏）、`/v1/models` 输出。

## 3. A2：SSE 流式输出

### 3.1 模型 A 流式

```bash
curl -N http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "pro",
    "stream": true,
    "messages": [{"role": "user", "content": "写三行关于秋天的短诗"}]
  }'
```

### 3.2 模型 B 流式

```bash
curl -N http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "flash",
    "stream": true,
    "messages": [{"role": "user", "content": "写三行关于秋天的短诗"}]
  }'
```

### 3.3 检查点

- [ ] 能看到多条 `data: {...}`，而不是一次性返回完整结果
- [ ] 最后有 `data: [DONE]`
- [ ] 每个 chunk 是合法 JSON（`[DONE]` 除外）
- [ ] 两个模型都能流式
- [ ] 响应头有 `X-Request-ID`
- [ ] `/admin/usage` 中对应记录 `stream=true`
- [ ] `first_token_ms` 有值，且小于 `latency_ms`

### 3.4 客户端中断

```bash
# 启动后 2 秒主动断开
curl -N --max-time 2 http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"pro","stream":true,"messages":[{"role":"user","content":"写一篇长文"}]}'
```

- [ ] 客户端断开后，网关停止读取上游
- [ ] usage 记录状态为 `cancelled`（或等价状态）
- [ ] 日志中能看到上游连接被关闭

### 3.5 流中途错误

用 pytest + mock 上游模拟“已发送首个 chunk 后返回错误”：

```bash
uv run pytest -q tests/test_streaming.py -k mid_stream_error -vv
```

- [ ] 返回统一 SSE 错误事件
- [ ] 随后发送 `[DONE]`
- [ ] 不重试、不切换模型
- [ ] usage 记录为 `error`

**证据建议**：保存流式输出片段、usage JSON、断连日志。

## 7. A6：统一错误码与重试

### 7.1 统一错误格式

所有错误都应返回：

```json
{
  "error": {
    "message": "human readable message",
    "type": "error_type",
    "code": "error_code",
    "param": null
  }
}
```

- [ ] 401 鉴权失败
- [ ] 404 未知模型/模板
- [ ] 422 参数校验/模板渲染/结构化失败
- [ ] 429 限流
- [ ] 502/503 上游失败/无可用路由

### 7.2 重试

```bash
uv run pytest -q tests/test_resilience.py -k retry -vv
```

- [ ] 500 会重试
- [ ] 超时会重试
- [ ] 429 会重试（如配置为可重试）
- [ ] 400 不重试
- [ ] 最多 3 次（按你的定义，README 写清是总尝试还是额外重试）
- [ ] 退避间隔递增（日志或测试断言）
- [ ] 流式已经开始后不重试

## 8. A7：按模型独立限流

配置一个较低的限流值（例如 `requests_per_minute: 2`、`burst: 1`），然后：

```bash
for i in 1 2 3 4; do
  curl -s -o /dev/null -w "%{http_code}\n" \
    http://localhost:8000/v1/chat/completions \
    -H "Authorization: Bearer $GATEWAY_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"model":"pro","messages":[{"role":"user","content":"hi"}]}'
done
```

- [ ] 前几次 200，超过限制返回 429
- [ ] 429 响应体是统一错误结构
- [ ] 有 `Retry-After` 头
- [ ] 模型 `pro` 被限流时，`flash` 仍可调用
- [ ] 重启服务后桶状态重置（单进程实现可接受）

**证据建议**：429 响应头/响应体、跨模型隔离结果。

## 9. A8：错误场景回归

| 场景 | 请求 | 期望 |
| --- | --- | --- |
| 错误 Key | `Authorization: Bearer wrong` | 401 + 统一错误 |
| 未知模型 | `"model": "not-exist"` | 404 + `model_not_found` |
| 缺消息 | 不传 `messages` | 422 + 参数错误 |
| 未知模板 | `gateway_prompt.id = "nope"` | 404 + `prompt_not_found` |
| 模板缺变量 | 少传变量 | 422 + 渲染错误 |
| 结构化失败 | 连续非法 JSON | 422 + `invalid_model_output` |
| 限流 | 超过 RPM | 429 + `rate_limit_exceeded` |
| 上游失败 | mock 500 / 无健康路由 | 502/503 + 上游错误 |

- [ ] 以上场景逐项验证
- [ ] 错误响应不泄露上游 Key、堆栈、内部路径
