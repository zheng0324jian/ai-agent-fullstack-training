## 章节定位

第一章是整门课的“模型调用层”地基：把一次能跑通的 API 调用，逐步做成**稳定、可控、可解析、可治理**的模型服务能力，为后续 Function Calling、Agent Loop、Context Engineering 等章节提供底座。

## 学习主线

```text
调通 API → 控住参数与上下文 → 错误处理与多模型 → 流式输出
→ Prompt 可控 → 结构化输出 → LLM Gateway 统一治理 → 统一模型调用服务
```

## 1. LLM API 调用基础（1-1 ~ 1-3）

### 1-1 Chat Completions 与 Responses API（26:24）

- 两类 API 的请求与响应结构
- messages 角色划分：system / user / assistant / tool
- Chat Completions 与 Responses API 的差异、选型与迁移思路
- 目标：先把一次模型调用跑通，理解请求和响应到底长什么样

### 1-2 模型参数、Token 与 Context Window（24:45）

- temperature、top_p、max_tokens 等参数的实际影响
- Token 的计算方式与上下文窗口边界
- 成本、延迟、输出长度之间的权衡
- 目标：知道一次调用“为什么贵、为什么慢、为什么被截断”

### 1-3 错误类型、异常处理与多模型调用基础（16:21，学习中）

- 模型调用失败的分类：网络、超时、限流、鉴权、服务端错误、内容安全等
- 重试、退避与降级策略
- 多模型适配层的设计
- 视频知识点：
  - 模型调用失败处理策略
  - 模型降级设计原则
  - 模型适配层设计与实现
- 目标：从“能调通”过渡到“调用失败也能兜住”

## 2. 流式输出（2-1 ~ 2-3）

### 2-1 Streaming 概述与 SSE（26:05）

- 流式输出的价值与适用场景
- SSE（Server-Sent Events）协议与数据分块格式
- 流式响应的生命周期

### 2-2 FastAPI 流式响应、前端消费与请求中断（41:59）

- FastAPI 中实现流式响应
- 前端如何消费流式数据、增量渲染
- 用户主动中断请求时的处理
- 目标：打通“后端持续产出 → 前端持续展示”的链路

### 2-3 流式输出异常处理与长文本输出的状态保存（15:00）

- 流式传输中途失败、超时与断连的处理
- 长文本输出的状态保存与恢复
- 目标：流式不仅要“能流”，还要“流得稳、断得回”

## 3. Prompt 工程（3-1 ~ 3-3）

### 3-1 System Prompt 的职责以及角色定义与行为约束（17:19）

- System Prompt 的职责边界
- 角色定义、行为约束与输出规范
- 目标：让模型“按角色、按规则”工作

### 3-2 Few-shot 与任务拆解（08:11）

- Few-shot 示例的设计与使用
- 将复杂任务拆解为可执行的子任务
- 目标：用示例和拆解提升输出稳定性

### 3-3 Prompt 模板、注入风险以及版本管理（16:55）

- Prompt 模板化与参数化
- Prompt 注入的常见风险与防护思路
- Prompt 的版本管理与迭代
- 目标：Prompt 从“随手写”变成“可维护的工程资产”

## 4. 结构化输出（4-1 ~ 4-2）

### 4-1 JSON Schema 与 Pydantic Model（15:55）

- JSON Schema 的基本结构与约束能力
- 用 Pydantic 定义输出模型
- 目标：把自然语言输出约束成可校验的数据结构

### 4-2 模型原生结构化输出纠错、重试与失败处理（22:26）

- 模型原生结构化输出的使用方式
- 输出不合规时的校验、纠错与重试
- 重试仍失败时的兜底策略
- 目标：结构化输出不仅“能解析”，还要“出错可恢复”

## 5. LLM Gateway（5-1）

### 5-1 LLM Gateway 大模型网关（33:07）

- 多模型统一接入与路由
- 鉴权、限流、配额与可观测性
- 降级、重试与统一错误处理
- 目标：把前面零散的调用能力收拢成统一入口
