## 1-2 模型参数、Token 与 Context Window

### Q1：temperature 的含义是什么？

- 关联课程：1-2 模型参数、Token 与 Context Window
- 记录日期：2026-10-31

**一句话回答**：`temperature` 控制模型生成时的**采样随机程度**。值越低，输出越确定、越保守；值越高，输出越随机、越发散。它不改变模型掌握的知识，只改变“每一步从概率分布里怎么挑下一个 token”。

**原理**：模型每一步会先给候选 token 打分（logits），`temperature` 在 softmax 前对分数做缩放：

```text
p_i = softmax(z_i / T)
```

- `T → 0`：概率集中到最高分 token，接近“每次选最大概率”的贪心解码
- `T = 1`：使用模型原始概率分布
- `T > 1`：分布被拉平，低概率 token 也有更多机会被选中
- 不同厂商的取值范围不同，常见为 0～2（OpenAI、DeepSeek 等），Anthropic 为 0～1

**实际效果**：

| 取值 | 表现 | 适用场景 |
| --- | --- | --- |
| 0～0.3 | 稳定、保守、重复性高 | 信息抽取、分类、代码、结构化输出、工具调用 |
| 0.5～0.8 | 相对平衡 | 通用问答、日常对话 |
| 0.9～1.2 | 发散、多样 | 头脑风暴、文案、创意生成 |
| >1.5 | 容易跑题、胡言乱语 | 一般不建议 |

注意：`temperature` **不是“聪明度”旋钮**。调高不会让模型更懂问题，只会让输出更多样，同时也更容易出现幻觉和格式错误。

**和 top_p 的区别**：

- `temperature`：缩放整个概率分布，影响所有候选 token 的相对机会
- `top_p`：只保留累计概率达到 p 的候选集，直接截掉长尾

两者都在控制随机性，**通常只调一个**。常见做法是 `top_p=1` 固定，只调 `temperature`；或者固定 `temperature=1`，用 `top_p=0.9` 左右截尾。两个都大幅调整，容易叠加出过度随机的结果。

**工程上的几个坑**：

1. `temperature=0` 也不保证完全可复现：GPU 浮点运算、批处理顺序、MoE 路由等都可能带来细微差异；需要复现时优先看厂商是否支持 `seed`。
2. 推理模型可能不支持或忽略 `temperature`：部分 reasoning 模型只接受默认值，传其他值会报错或被静默忽略。
3. 结构化输出场景优先低温：JSON Schema、Pydantic 解析、Function Calling 参数生成，低温更稳。
4. RAG 问答也不宜太高：0.2～0.5 更利于忠于检索内容，减少自由发挥。

**结合本章**：可以把 `temperature`、`top_p`、`max_tokens` 一起理解——前两个控制“怎么选”，后者控制“选多久/输出多长”。

## 2-1 Streaming 概述与 SSE

### Q1：SSE 是什么？怎么用？

- 关联课程：2-1 Streaming 概述与 SSE
- 记录日期：2026-10-31

**一句话回答**：SSE（Server-Sent Events）是一种基于 HTTP 的**服务器单向推送**协议。客户端发起一个普通 HTTP 请求后，服务器保持响应不关闭，按固定文本格式持续把数据推给客户端。

**通信过程**：

1. 客户端发起请求（浏览器可用 `EventSource`）
2. 服务器返回 `Content-Type: text/event-stream`，并保持连接
3. 服务器不断写入一条条事件
4. 连接断开后，浏览器默认会自动重连

**数据格式**：每条消息以空行结束。

```text
data: 第一段

event: token
data: {"text":"你"}

id: 42
data: 第二段

: heartbeat
```

- `data:`：消息内容，可写多行，客户端会拼接
- `event:`：自定义事件名，配合 `addEventListener` 使用
- `id:`：事件 ID，断线重连时浏览器会带上 `Last-Event-ID`
- `retry:`：重连间隔（毫秒）
- 以 `:` 开头的是注释，常用来做心跳

**客户端最小示例**：

```js
const es = new EventSource("/api/chat/stream");

es.onmessage = (e) => {
  console.log(e.data);
};

es.addEventListener("done", () => {
  es.close();
});
```

注意：原生 `EventSource` 只支持 GET，不能自定义请求头和请求体。

**服务端最小示例（FastAPI）**：

```python
from fastapi.responses import StreamingResponse

async def event_stream():
    yield "data: 你好\n\n"
    yield "data: 世界\n\n"
    yield "data: [DONE]\n\n"

@app.get("/stream")
async def stream():
    return StreamingResponse(
        event_stream(),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )
```

**关键特点**：

- 单向：只能服务器推给客户端；客户端要发消息，需要再发一次请求
- 纯文本、UTF-8，不能直接传二进制
- 基于 HTTP，穿过代理和防火墙通常比 WebSocket 容易
- 自带断线重连和事件 ID 续传机制
- LLM 流式输出普遍采用 SSE 格式，例如 OpenAI 兼容接口的 `data: {...}` 和 `data: [DONE]`；但请求通常是 POST + JSON，所以前端多用 `fetch` 读取 `ReadableStream`，而不是 `EventSource`

**常见坑**：

- Nginx 等代理默认会缓冲响应，导致内容“攒一批才吐出来”；需要关闭缓冲（`proxy_buffering off` 或 `X-Accel-Buffering: no`）
- 消息之间必须有空行，否则客户端不会派发
- 长连接需要心跳，避免中间设备超时断开
- HTTP/1.1 下浏览器对同域名连接数有限制，开多个 SSE 标签页可能互相挤占

**和 WebSocket 怎么选**：

| 对比项 | SSE | WebSocket |
| --- | --- | --- |
| 方向 | 服务器 → 客户端 | 双向 |
| 协议 | HTTP | 独立协议（握手升级） |
| 数据 | 文本 | 文本 + 二进制 |
| 重连 | 浏览器内置 | 需要自己实现 |
| 适用场景 | LLM 流式输出、通知、进度推送 | 聊天室、游戏、协同编辑 |

只需要服务器持续推送文本时，SSE 更简单；需要双向实时通信时，选 WebSocket。

## 补充问答（2026-11-03）

### Q1：Prompt Engineering 在 Agent 项目中是什么作用？

- 关联课程：第一章 3-1 ~ 3-3 Prompt 工程
- 记录日期：2026-11-03

**一句话回答**：Prompt 是模型的**行为契约 / 策略层**，决定模型“想怎么做”；Harness 决定“实际能怎么做”。它定义角色、目标、边界、流程、工具策略、输出与完成标准、失败升级，但不替代权限、Schema、沙箱和状态机。

**完整整理**：见知识库 [Agent Prompt Engineering](../knowledge_base/agent_prompt_engineering.md)。

### Q2：Prompt 是用户输入的，还是内置在 Agent 里的？

- 关联课程：第一章 3-1 ~ 3-3 Prompt 工程
- 记录日期：2026-11-03

**一句话回答**：两者都有，但层级不同。System Prompt、工具描述、Few-shot、模板是内置的；用户输入只是填入 `<task>` 的任务变量；运行时上下文由程序每轮生成。最终 Prompt 由代码组装，用户输入不能覆盖系统规则。

**完整整理**：见知识库 [Agent Prompt Engineering](../knowledge_base/agent_prompt_engineering.md)。

### Q3：Pydantic 是什么？

- 关联课程：第一章 1-5 Structured Output；第二章 2-2 Tool Runtime
- 记录日期：2026-11-03

**一句话回答**：Pydantic 是 Python 的数据校验与序列化库。它用类型注解定义数据契约，在运行时校验、转换、序列化，并能生成 JSON Schema；在 Agent 项目中主要用于结构化输出、工具参数 / 返回值校验，以及 FastAPI 请求 / 响应模型。

**完整整理**：见知识库 [Pydantic](../knowledge_base/pydantic.md)。

## 补充问答（2026-11-05）

### Q1：Trace 是什么意思？

- 关联课程：第一章 2-3 流式输出；1-6 LLM Gateway；第二章 2-4 工具治理
- 记录日期：2026-11-05

**一句话回答**：Trace 是**一次 Agent Run 的完整执行轨迹**，不是报错时的 Stack Trace。它用 `trace_id` 把模型调用、工具调用、重试、Checkpoint、错误等串成一条有因果关系的链路，用来定位“为什么慢、为什么贵、为什么失败”，并支持性能分析、成本核算、质量回归、恢复与审计。

**完整整理**：见知识库 [Agent Trace](../knowledge_base/agent_trace.md)。

## 补充问答（2026-11-06）

### Q1：LLM Gateway 和 Agent Harness 的区别是什么？

- 关联课程：第一章 1-6 / 1-7 LLM Gateway；第三章 3-5 Agent Harness
- 记录日期：2026-11-06

**一句话回答**：LLM Gateway 是**模型访问层**，管“模型怎么被调用”——路由、鉴权、限流、重试、fallback、结构化输出、Token / 成本 / 延迟；Agent Harness 是**任务执行层**，管“任务怎么被完成”——Loop、Context、Tool Runtime、State / Checkpoint、Governance、Sandbox、验证、恢复和交付。两者是上下游协作关系，不是替代关系。

**完整整理**：见知识库 [LLM Gateway vs Agent Harness](../knowledge_base/llm_gateway_vs_agent_harness.md)。
