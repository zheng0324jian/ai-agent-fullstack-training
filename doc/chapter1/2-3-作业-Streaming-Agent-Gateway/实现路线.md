# 实现路线：Streaming Agent Gateway

> 目标：把作业拆成可逐步验收的工程阶段，避免一上来就同时改协议、并发、存储和前端。
> 参考起点：`course_code/week01/1-3/app.py`（已有 RunEvent、内存 Store、SSE、三个接口、Web 页面）。

## 0. 先定范围：MVP 与完整版

| 范围 | 内容 | 说明 |
| --- | --- | --- |
| MVP（必须先交） | RunEvent 协议、SSE 编解码、Model Adapter、Run Store、Agent Loop、创建/订阅/取消、断线重放、取消传播、边界测试 | 对应课件第 1–9 步 |
| 完整版（作业要求） | MVP + Checkpoint、数据库持久化、Trace、错误协议、Web/CLI 双客户端、11 项测试、演示证据 | 对应课件第 10–11 步 |

**建议顺序：先让协议和取消闭环跑通，再做持久化。** 否则很容易在数据库和前端之间来回改协议。

## 1. 阶段一：协议层（第 1–2 步）

### 任务

- [ ] 定义 `EventType`：8 类对外事件。
- [ ] 定义 `RunEvent`（建议 Pydantic v2）：
  - `schema_version: Literal["1"] = "1"`
  - `run_id: str`
  - `seq: int = Field(ge=0)`
  - `type: EventType`
  - `created_at: datetime`
  - `data: dict[str, Any]`
- [ ] 实现 `encode_sse(event) -> bytes`。
- [ ] 实现 `encode_heartbeat() -> bytes`。
- [ ] 实现客户端/测试用 `feed_bytes()` 解析器：`buffer → lines → frames → RunEvent`。
- [ ] 写 TC01–TC06 六个编码测试。

### 完成标准

- 中文、换行、引号、反斜杠、空 delta、>64KB、任意字节切分都不破坏协议。
- 心跳不占用 `seq`。
- 未知事件类型不会让解析器崩溃。

### 对应文件建议

```text
app/events.py
app/sse.py
tests/test_events.py
tests/test_sse.py
```

## 2. 阶段二：Model Adapter（第 3–4 步）

## 3. 阶段三：Run Store 与 Agent Loop（第 5–6 步）

### 任务

- [ ] 定义 `RunStore` 接口：
  - `create(run_id)` / `get(run_id)`
  - `append(run_id, type, data) -> RunEvent`
  - `read_after(run_id, seq) -> list[RunEvent]`
  - `request_cancel(run_id)`
  - `finish(run_id, status)`
- [ ] 实现 `MemoryRunStore`：状态、事件列表、`next_seq`、取消信号、条件变量。
- [ ] 实现 `AgentLoop`：
  - [ ] 写 `run.started`。
  - [ ] 消费 `StreamingModel`。
  - [ ] 把 `text.delta` 转成对外事件。
  - [ ] 把工具调用转成 `tool.started` / `tool.completed`。
  - [ ] `finish_reason == "length"` → `run.failed`（`OUTPUT_TRUNCATED`）。
  - [ ] 正常结束 → `run.completed`。
  - [ ] 取消 → `run.cancelled`。
  - [ ] 异常 → `run.failed`（稳定错误码）。
- [ ] 确认 Loop 不依赖 FastAPI 的 `Request`。

### 完成标准

- 事件 `seq` 从 0 单调递增。
- 一个 Run 只有一条终态。
- 取消信号能让 Loop 在下一步之前停止。
- 文本结束不会直接写成 `run.completed`，要先看 `finish_reason`。

### 对应文件建议

```text
app/store/base.py
app/store/memory.py
app/loop.py
tests/test_store.py
tests/test_loop.py
```

## 4. 阶段四：API 与取消（第 7 步）

### 任务

- [ ] `POST /v1/runs`：
  - [ ] 生成 `run_id`。
  - [ ] 创建后台任务。
  - [ ] 立即返回 `202` + `run_id`。
- [ ] `GET /v1/runs/{run_id}/events`：
  - [ ] `Last-Event-ID` 解析。
  - [ ] 按 `seq` 重放历史事件。
  - [ ] 持续推送新事件。
  - [ ] 心跳。
  - [ ] 客户端断开只结束订阅，不取消 Run。
- [ ] `POST /v1/runs/{run_id}/cancel`：
  - [ ] `created/running` → `cancelling`。
  - [ ] 已终态 → 幂等返回当前状态。
  - [ ] 传播取消信号到 Loop / Model / Tool。
- [ ] 状态机用 CAS 或锁保证并发安全。
- [ ] 加 `404` / `400` 错误处理。

### 完成标准

- 创建接口不被模型阻塞。
- 订阅重连不触发第二次模型调用。
- 取消后最终出现且只出现一条 `run.cancelled`。
- 完成/取消并发时不会出现两条终态。

### 对应文件建议

```text

tests/test_api.py

```

## 6. 阶段六：恢复与持久化（第 9–10 步）

### 任务

- [ ] 失败阶段判定：
  - [ ] A：连接/响应阶段，无事实 → 有限重试。
  - [ ] B：首事件后断流 → 禁止盲目拼接，走重放/查状态。
  - [ ] C：大量事件后 → 先查上次状态，再决定重放或重跑。
- [ ] 重试策略：
  - [ ] 白名单：DNS、网络、429、503。
  - [ ] 黑名单：401、400、Schema、内容拒答。
  - [ ] 限制：`max_attempts`、`max_total_seconds`、backoff、jitter、Run budget。
  - [ ] 已产生业务事件 → 不自动重跑。
- [ ] Checkpoint：
  - [ ] `loop_step`。
  - [ ] `completed[]`。
  - [ ] `next_cursor`。
  - [ ] `context_digest`。
  - [ ] `tool_state[]`。
  - [ ] `version`。
- [ ] 持久化：
  - [ ] 课堂版可用 SQLite 或内存 + 文件快照。
  - [ ] 生产版 PostgreSQL：`run_events(run_id, seq)` 唯一约束。
  - [ ] Redis 只做通知，不作为事实来源。
  - [ ] 文本 delta 批量写入；状态/工具事件立即写入。
- [ ] 进程重启恢复：
  - [ ] 读 checkpoint。
  - [ ] 恢复 Run 状态。
  - [ ] 从 `next_cursor` 继续。

### 完成标准

- 杀掉进程再启动，能从 checkpoint 继续，不重复已完成步骤。
- 断线重连只重放事件，不重新调用模型。
- 外部副作用超时被标记 `unknown`，不会盲目重试。

### 对应文件建议

```text

app/store/postgres.py
app/retry.py
tests/test_replay.py
tests/test_checkpoint.py
tests/test_retry.py
```

## 8. 如果时间有限：优先级建议

**不要砍：**

- RunEvent 协议与 `seq`。
- SSE 编解码与拆包/粘包。
- 创建/订阅/取消三接口。
- 单一终态与取消状态机。
- 断线重放不重跑。
- 取消传播与部分输出保存。
- 至少 10 项边界测试。

**可以降级：**

- PostgreSQL → SQLite / 文件快照（只要 checkpoint 能恢复）。
- Redis → 进程内通知（单机演示足够）。
- IDE 客户端 → 只做 Web + CLI。
- 复杂前端 → 简单事件日志 + 文本区域。

**不要用“页面能打字”代替验收：**

- 必须有取消、重连、单一终态、重放、checkpoint 的证据。
- 必须有测试，而不是只靠手工点一遍。

## 9. 建议的 5 分钟演示脚本

1. 启动服务，说明环境变量与架构图。
2. 创建一个较长回答的 Run，展示：
   - `POST /v1/runs` 立即返回 `202 + run_id`；
   - 首 delta 到达时间（TTFT）；
   - 页面/CLI 持续增长。
3. 手动断开订阅，再重连：
   - 展示 `Last-Event-ID`；
   - 事件补齐且不重复；
   - 模型调用次数没有增加。
4. 点击取消：
   - 展示 `running → cancelling → cancelled`；
   - 展示已输出文本和 6 项取消状态被保存；
   - 页面停止增长。
5. 杀掉进程再启动，展示从 checkpoint 恢复（或展示恢复测试）。
6. 运行 `pytest -q`，展示测试通过。
7. 展示一次 `run.failed` 的稳定错误码与 Trace 字段。
