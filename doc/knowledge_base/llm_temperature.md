# LLM Temperature

> 分类：LLM / 模型参数
> 相关课程：第一章 1-2 模型参数、Token 与 Context Window
> 整理日期：2026-10-31

## 定义

`temperature` 控制模型生成时的**采样随机程度**。值越低，输出越确定、越保守；值越高，输出越随机、越发散。它不改变模型掌握的知识，只改变“每一步从概率分布里怎么挑下一个 token”。

## 原理

模型每一步会先给候选 token 打分（logits），`temperature` 在 softmax 前对分数做缩放：

```text
p_i = softmax(z_i / T)
```

- `T → 0`：概率集中到最高分 token，接近贪心解码
- `T = 1`：使用模型原始概率分布
- `T > 1`：分布被拉平，低概率 token 也有更多机会
- 不同厂商的取值范围不同，常见为 0～2（OpenAI、DeepSeek 等），Anthropic 为 0～1

## 取值与效果

| 取值 | 表现 | 适用场景 |
| --- | --- | --- |
| 0～0.3 | 稳定、保守、重复性高 | 信息抽取、分类、代码、结构化输出、工具调用 |
| 0.5～0.8 | 相对平衡 | 通用问答、日常对话 |
| 0.9～1.2 | 发散、多样 | 头脑风暴、文案、创意生成 |
| >1.5 | 容易跑题、胡言乱语 | 一般不建议 |

`temperature` 不是“聪明度”旋钮。调高不会让模型更懂问题，只会让输出更多样，同时更容易出现幻觉和格式错误。

## 与 top_p 的关系

- `temperature`：缩放整个概率分布，影响所有候选 token 的相对机会
- `top_p`：只保留累计概率达到 p 的候选集，截掉长尾

两者都在控制随机性，通常只调一个：

- 固定 `top_p=1`，只调 `temperature`
- 或固定 `temperature=1`，用 `top_p=0.9` 左右截尾

两个都大幅调整，容易叠加出过度随机的结果。

## 工程实践

1. `temperature=0` 也不保证完全可复现：GPU 浮点运算、批处理顺序、MoE 路由等都可能带来细微差异；需要复现时优先看厂商是否支持 `seed`。
2. 推理模型可能不支持或忽略 `temperature`：部分 reasoning 模型只接受默认值，传其他值会报错或被静默忽略。
3. 结构化输出优先低温：JSON Schema、Pydantic 解析、Function Calling 参数生成，低温更稳。
4. RAG 问答不宜太高：0.2～0.5 更利于忠于检索内容，减少自由发挥。

## 相关参数

- `top_p`：核采样，控制候选集大小
- `max_tokens` / `max_output_tokens`：控制输出长度上限

可以一起理解：前两个控制“怎么选”，后者控制“选多久/输出多长”。
